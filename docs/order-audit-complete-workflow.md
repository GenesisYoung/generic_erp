# 订单评审完整流程补齐说明

本次补齐页面原来只有接口、没有入口的环节。前端继续使用真实API；无演示回退，无预先批准的业务规则，无自动扩大的账号权限。

## 已打通的操作

| 环节 | 页面操作位置 | 行为 |
| --- | --- | --- |
| 查看／制定规则 | 列表右上“业务规则” | 查看批准版本、待批草稿、规则历史及当次内容；配置时区、受理条件、必备资料、完成节点和凭证 |
| 独立批准规则 | 同一弹窗 | 非提交人的授权审批人批准／驳回，保留版本和依据；已受理任务沿用快照 |
| 草稿及资料 | 新增评审／任务详情 | 新建首轮、补资料、上传任务专属文件、关联凭证；后续轮次由获批重评生成 |
| 受理与执行 | 任务详情原有按钮 | 主管受理、开始、阻塞、解除、提交成果；期限、责任及证据由后端检查 |
| 主管业务确认 | 任务详情“主管业务确认” | 针对当前成果版本通过／退回，禁止本人确认本人成果；BUSINESS_APPROVAL模式通过后形成批准节点完成时间 |
| 独立核验 | 任务详情“独立核验” | 符合／不符合／需补证／归责争议；与业务确认分别记录 |
| 变更申请 | 任务详情“提出变更申请” | 改期、受理后资料修正、撤销、不予承接、重开、新轮次重评；只显示当前状态允许的事项 |
| 变更审批 | 详情“变更申请与审批” | 展示理由、原期限、新期限、修正资料、提交与审批人和凭证；非申请人的授权主管批准／驳回 |
| 重开及重评 | 获批后的任务详情 | 重开回到退回状态，保留首版与历史；重评生成新草稿，可查看上一轮／进入下一轮 |
| 成果快照 | 详情“成果快照与核验依据” | 查看任一版本的结论、填报／批准节点／提交时间、资料与规则快照、历次业务确认和核验 |
| 凭证下载 | 详情“关联凭证” | audit:任务凭证通过带登录权限的请求下载，保留原文件名；已有appendix凭证继续使用原附件管理入口 |
| 列表导出 | 列表“导出筛选结果” | 导出最后一次查询的全量匹配记录，不限当前页；CSV、最多10000条，后端再次检查导出权限和数据范围 |

保存失败保留输入；版本冲突不覆盖其他人的修改，需要刷新核对。所有写入有防重复点击、幂等键和后端并发版本校验。未受理、阻塞、撤销、争议等不在前端自动改绩效分母。

## 权限与生效

后端metadata新增currentUserId、canConfigureRules、canApproveRules、canExport；详情allowedActions新增confirm-business、request-change、approve-change、upload-evidence。页面按后端返回显示入口，自批等限制仍由后端执行。新增reviewParentTaskId／reviewChildTaskId作为新获批重评的跳转关系，保存在任务文档中，不新增数据库列。旧记录没有跳转关系时，仍可按订单查询各轮次。

1. 重新构建并重启后端，刷新前端，让新增能力字段生效。
2. 初次启用完整流程时，评审执行 `src/main/resources/db/order_audit_workflow_permissions.sql`，补齐权限目录与该页面的可分配选项。脚本未在本次工作中对业务库执行，不会给账号自动授权。
3. 通过已有权限管理按岗位分配：员工通常需要read/create/update/execute/submit/change.request；主管按职责增加accept/confirm/verify/approve及team范围；规则制定与批准分别授予rules.configure和rules.approve；导出另授export。每个动作还要求read。这里只说明组合方式，实际授权由公司决定。
4. 使用两名不同人员制定并批准实际规则。规则凭证可以先在本人可处理的真实任务详情上传，再复制编号；或使用本人已有的有效受控附件。规则字段不默认填公司尚未确认的资料名称或时限。
5. 按下列路径验收。

ROOT也不能核验自己提交的成果，不能自批变更或规则。普通菜单访问只提供读取，不自动提供写入、审批或跨部门范围。

## 建议验收路径

- 主流程：配置人提交规则→另一人批准→员工建立草稿／补齐资料→主管受理→员工处理并提交→如规则要求则由独立主管业务确认→独立核验符合→已核验。
- 补证：待核验→需补证→员工提交新版→核验，确认首版及其旧核验仍可查。
- 阻塞／改期：登记阻塞及下一动作→申请改期→另一人批准，确认原期限保留→解决并附证据→恢复处理。
- 资料修正：受理后申请完整修正资料→另一人批准→阻塞跟进→提交新版→核验；原订单、轮次、接收时间不被表单精度截断。
- 重开：已核验→申请重开→另一人批准→补充修正并提交新版→重新核验。
- 重评：已核验→申请新轮次重评→另一人批准→进入新轮草稿，重新补资料、受理和核验；原轮次保留。
- 撤销／不承接：发起申请→独立批准→已撤销；未受理的不承接保留决定理由。任务已撤销后，其他待批申请不能再获批改变任务，可驳回清理。
- 权限：只读者无写入口；申请人无自批入口；直接调用非法操作仍被后端拒绝；附件、历史及导出遵守相同任务范围。

## 验证结果及边界

前端35项相关测试通过，含新增规则、主管确认、申请审批、失败保留输入、下一轮跳转、快照与下载、导出契约测试；类型检查及生产构建通过。后端69项测试通过，包含资料修正、不承接、撤销后审批拦截、新轮跳转、权限能力和文件下载响应头验证。

本次测试使用隔离数据库及前端请求模拟，没有用真实职员账号新增业务任务或批准公司规则。实际数据库迁移／权限分配／业务规则批准仍需在正式使用环境完成。老ERP原单自动对接、正式绩效结算、旧系统附件下载入口与企业文件扫描不属于本次新增流程，未伪装为已实现。
