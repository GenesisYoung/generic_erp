# 独立“凭证管理”菜单

入口：`/#/pmc/evidence`，侧边栏名称“凭证管理”，独立于订单评审任务。

## 使用

1. 在凭证管理选择文件，填写用途，点击上传。支持PDF、PNG、JPEG、UTF-8文本，非空且不超过20MB。
2. 上传成功返回完整的 `evidence:UUID` 编号，可直接复制。上传失败保留文件与用途，未修改内容的重试沿用幂等键，避免超时重复存储。
3. 将编号填写到本人制定规则、提交成果、申请变更或办理审批的凭证字段。无需先创建订单、临时草稿或虚构业务单据。
4. 列表查询本人文件名、用途或编号，支持分页、复制编号、按原文件名下载。凭证不可覆盖或删除，以保留已引用业务的证据。

## 权限和关联

- 菜单及列表读取：`menu.evidence.read`。上传另需 `menu.evidence.create`。
- 直接授予该菜单只派生读取，不自动提供上传、订单操作或部门范围。
- 个人列表与直接下载始终限制本人，包括ROOT。知道别人的编号不代表可以引用或下载。
- 本人合法引用到订单任务后，任务授权人员可从任务关联凭证入口下载。关联包括资料、成果、核验、业务确认及合法提交的资料修正申请。
- 本人合法引用到规则草稿或批准记录后，有规则配置或批准权限的人员可从“业务规则→规则关联凭证”查看已关联的独立凭证，以支持独立审批。这个入口不开放对私人文件库的浏览，也不允许通过猜编号下载未关联的文件。
- 原 `audit:UUID` 仍为任务专属凭证，原 `appendix:ID` 仍按既有有效附件处理。新独立入口返回 `evidence:UUID`，不改变旧文件归属。

文件保存在原配置目录的personal子目录，路径由服务端生成。上传校验文件名、大小、扩展名与内容签名，下载固定为附件并检查文件路径边界。没有自动接企业文件扫描。

## 接口

- GET `/api/pmc/evidence/metadata`：canUpload。
- GET `/api/pmc/evidence?keyword=&page=1&size=20`：仅本人items、total，size为20/50/100。
- POST `/api/pmc/evidence`：multipart file、purpose及Idempotency-Key，返回evidenceRef、fileName、purpose、size、uploadedAt。无taskId。
- GET `/api/pmc/evidence/{ref}/download`：本人文件流。
- 现有任务凭证下载接口现支持已合法引用的evidence编号。
- GET `/api/pmc/order-audit-tasks/rules/evidence/{ref}/download`：独立规则凭证下载，校验规则维护／批准权限及实际关联。

## 数据与菜单登记

`src/main/resources/db/personal_evidence_v1.sql` 新增pmc_personal_evidence表、读取／上传权限代码、顶层菜单及可分配权限。脚本只为已有ROOT账户补菜单可见记录，不给职员新增权限，不修改旧凭证或业务任务。职员由管理员通过现有“权限分配”授予菜单及上传能力。

后端新增独立上传服务及引用校验。规则状态新增evidenceRefs记录已验证并关联的规则凭证，旧规则对象可继续读取，不需要修改旧任务凭证表。

生效时需要重新构建并重启后端，刷新前端。实际业务规则仍由公司指定人员制定和独立批准，独立上传不会自动产生业务批准。

验证：后端81项测试通过，覆盖独立上传、无订单初始化规则批准、幂等、私人列表与ROOT隔离、越权引用拒绝、任务／规则授权下载，以及资料修正中新凭证的合法引用。前端42项测试、类型检查和生产构建通过。测试使用隔离数据，没有替职员上传实际文件或批准业务。
