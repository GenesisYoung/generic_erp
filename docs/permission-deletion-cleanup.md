# 权限删除后关联残留修复

## 已确认原因

权限列表按 permission_tb.is_enabled=1 查询；原删除接口仅把 is_enabled 改为 0，没有清理关联。
用户权限分配列表通过菜单注册记录查权限时没有过滤已停用权限，所以权限列表已经隐藏编号 113，分配页仍显示 menu.evidence.create。
2026-11-18 只读核对：编号 113 已停用，残留 1 条菜单注册，其他四种关联无残留。这里删除的是权限目录项，不是上传的凭证文件。

## 修复行为

- /api/admin/permissions/delete：仅停用传入的真实编号；同一事务删除菜单注册、用户页面授权、角色授权、指定权限的用户菜单关联、动作关联。permission_id 为 NULL 的基础菜单授权保留。
- /deleteRoot：按完整权限码及其点分隔子级停用，在同一事务清理关联；create 不匹配 creator，百分号和下划线不作为通配符。
- 停用目录记录仍保留。重复删除可清理历史残留。重新启用同名权限先移除历史关联，必须重新注册、重新授权。
- 用户分配列表过滤停用权限和停用授权；注册、用户授权、角色授权接口拒绝新增停用权限的关联。取消已有授权仍允许。
- 前端缓存页重新激活时刷新当前权限列表。

## 已有数据修复

src/main/resources/db/repair_deleted_evidence_permission_links.sql 仅处理编号 113 且权限码完全匹配、当前仍停用的记录；不会重新创建该权限或恢复注册。可重复执行。
清理数据不能代替部署代码：需要重启后端加载本次修复，再刷新前端页面。
未自动恢复 menu.evidence.create；如果仍需要上传功能，应由管理员明确重新添加该权限，再注册到凭证菜单并分配给目标用户。

## 验证

隔离 H2 事务测试覆盖全部关联清理、基础授权保留、编号删除不影响子级、分组删除边界、重复删除、重新启用不恢复授权以及失败回滚；另覆盖停用权限的查询和授权保护。
