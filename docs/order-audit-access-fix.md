# PMC订单评审菜单授权无法访问：诊断与修复

已只读核对现有授权：两位PMC账户的订单评审菜单授权均启用，读取权限代码也存在且启用；原有效权限查询未把user_nav_menu中的直接菜单访问纳入读取权限，导致前端路由和后端接口均拒绝访问。ROOT绕过权限检查，因此不受影响。该菜单没有绑定默认permission_id，不能依靠菜单默认绑定推断权限。

修复仅针对精确路由 `/pmc/order-audit-task`：启用的直接基线菜单授权（permission_id为空）派生精确的 `menu.order-audit-task.read`。要求菜单、授权及读取权限代码均启用。不会派生create/update/submit/verify/approve或team/all范围。已有角色和单独权限审批继续有效；撤销直接菜单授权只移除该路径派生的读取权限，若角色仍授予读取则仍可读。

为避免间接提权，授予该菜单、创建或修改菜单指向该路由时，操作者必须持有订单评审read权限。取消授权仍可执行。前端每次进入受保护路由前重新读取权限，避免其他会话刚修改授权而本会话仍持有旧缓存。

验证：后端59项测试通过，含新增8项读取权限、撤销、停用、角色兼容和防间接提权测试；前端类型检查和构建通过。对当前数据库执行修复后的只读查询，两位PMC账户均返回精确的read权限。未修改数据库授权记录，未使用职员账号执行业务写入。

生效：重新构建／重启后端，然后刷新前端页面。现有菜单授权无需重新勾选。业务写入和主管审批权限需按岗位另行分配；部门数据范围仍按原规则执行。仅有菜单授权时能进入页面查看授权范围内数据，不会自动得到新增、受理或核验按钮。
